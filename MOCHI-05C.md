# MOCHI-05C — account picker and phone startup

Opening Mochi through Pocket now opens a fictional account picker on first use. Users can select/create a profile, revisit profile management, refresh stale account data, or explicitly open unassigned legacy chats. The inbox offers Switch Mochi account. Last-used / always-picker preferences persist independently for each supported logical phone.

Source evidence: `PocketController.deviceIdentity()` and `pocketDeviceKey()` define the stable semantic key as encoded chat ID, character ID and device-owner actor ID; ephemeral surface IDs are excluded. `storedPhoneKey()` verifies those fields against the real user's saved native phone metadata. Backend resolution uses only `userStorage.getJson(statePath(...))`; it never calls `loadState`, normalizes/saves phones, or reads RP messages/clocks/memories into generation. The key is scoped to one logical phone in one Pocket chat context, not a physical handset carried between unrelated RP chats. Missing/unverified persisted phone identity visibly falls back to a shared real-user preference; no invented phone key.

Selections/preferences are optional fields in the same atomic account bank (up to 1,000 logical phone entries). Stale bank revisions fail safely. Archived/deleted pointers open the picker rather than another identity. Switching ignores stale responses and clears visible notifications while retaining stored unread records and room drafts. Interactive cancellation is scoped to the originating phone when supported; server-owned schedules remain independent. Generation rechecks the phone's selected fictional identity before acceptance and commit. Pending requests are registered before asynchronous phone resolution to preserve Stop semantics.
